# 视频对话记录

交付能定位回音频的对话文字稿；将“识别说了什么”和“判断是谁说的”分开。默认本地提取音频、转写和提取声纹，由当前 LLM 复核证据并统一标签，不额外要求在线 LLM API。LLM 可能帮助发现问题，但不预设它比声纹模型更准确。

## 输入和工作目录

- 接受视频或音频路径，可选已有文字记录、术语表、参会人数、已确认人物的参考发言。复用用户在当前任务中已提供的答案。
- 每场会议使用独立输出目录。保留源视频、源文字、原始标签和每轮修改，不更改其他会话正在处理的目录。
- 不知道真实姓名时用“说话人1”等稳定标签；不推测姓名、职位或性别。用户说“只有一位女性”时，请其给出一个确认的时间或原话，用声音匹配统一该参考人物，不以音高分类性别。
- 可在等待参考发言期间完成转写和初步分离；缺少参考不阻塞整项任务。不得跨会议沿用某人的声纹或自动假定人数相同。

## 本地处理

先读 [references/local-runtime.md](references/local-runtime.md) 确认本机环境、模型和命令；换机器时核实位置。模型不随 Skill 复制，无需为每场会议安装依赖。

1. 用 ffprobe 检查时长，用 ffmpeg 提取 16kHz 单声道 WAV。记录输入路径、大小、修改时间、时长、参数和模型路径。
2. 用 `scripts/process_audio.py` 执行 `transcribe` 与 `diarize`。二者独立，CPU 允许时可并行；检查退出状态和日志，进度输出不能当成完成。保留词级 `transcript.jsonl` 和原始 `speakers.json`。
3. 自动聚类得到的是候选组，不是确定人数。用户仅估计人数范围时，不取中间值强行凑组。确知人数时可作约束，但仍需检查误合并。
4. 已有文字记录可用于正文和术语参考，必须与视频重新对齐，原时间戳可能有偏移。明确文字来源，保留独立音频识别结果。

## 单独完成说话人复核

初步分离后读 [references/speaker-review.md](references/speaker-review.md)。用 `scripts/speaker_evidence.py` 提取选定片段的声纹、计算相似度、导出试听。不要只给 LLM 组号或纯文本，让它凭语义猜人物。

建立 `review-segments.json`：每段含稳定 `id`、`start`、`end`、原 `speaker`，可选 `text`。长段或可能换人的段拆成短窗口，并保留原段对应关系。仅用户已确认的参考可设 `confirmed_reference: true`；可登记同一人的多个已确认参考。

LLM 负责：

- 对照声纹、参考发言、代表片段和上下文，提出重复分组候选，检查一个组是否混入多人。
- 分别列出支持、反对和不足。话题相同、称呼习惯、发言风格只能用于找候选，不足以支持合并。
- 对冲突组逐段复核，必要时只改部分片段，不用整体映射抹掉组内差异。
- 有音频理解能力且实际读取了片段，才可报告听校；否则进行有限的数值及文字复核，并提供试听。
- 只就影响大的模糊参考向用户提问，保留不确定部分也应交付可用初稿。

把结果写入 `review-decisions.json`，用 `scripts/apply_speaker_map.py` 应用到副本并生成审计。不能只交建议：证据充分的修改实际进入最终标签和文字稿，证据不足的标“疑似某人”或“待确认”。

## 组装文字稿

- 以词时间和声纹区间的重叠建立映射；同一位置有不同可信标签时标交叠或切换，不强归一人。
- 有原记录时按规范化文本顺序对齐，保留正文。未匹配处只在相邻可靠时间点内估算，长缺口标“时间对齐待确认”，不要伪造精确时间。术语纠错和标签修改分开记录。
- 合并相邻同标签发言，不跨明显换人或长停顿；任务内编号保持稳定。
- 可按本场数据编写小型组装脚本；不要调用带上场会议标题、固定参考时间和固定输出名的归档脚本。

## 交付和核对

默认输出 TXT、Markdown、候选说话人表、待核对清单及少量试听；机器可读结果和审计放处理子目录。不自动生成字幕、纪要或 PPT。

检查正文覆盖、首尾时间、时间顺序、空段、参考标签、合并前后文本和时间未改，以及不确定片段是否保留。抽查开头、中段、结尾和各主要人物；未听校时称自动复核，不能称逐段人工校对完成。

报告输出链接、已统一的标签和剩余不确定性。相似度不是正确率，组数不是人数；不能以“组数更少”或“LLM 已审核”证明准确率提高。
