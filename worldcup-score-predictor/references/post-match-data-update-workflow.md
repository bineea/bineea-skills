# 已结束比赛数据更新规范

当用户要求“更新已结束比赛”“补齐赛后数据”“更新球队或球员表现”时，自动执行本规范。用户无需逐项指定字段、来源或更新步骤。

## 默认更新范围

1. 用户指定具体比赛时，只更新指定比赛。
2. 用户指定日期、轮次或比赛列表时，更新该范围内所有已结束比赛。
3. 用户只说“更新已结束比赛数据”且未指定范围时：
   - 先运行数据库覆盖审计；
   - 更新数据库内所有 `missing` 和 `partial` 的已结束比赛；
   - 按比赛日期从新到旧处理；
   - 不自动扩展到数据库外的其他赛事。
4. 用户要求更新“今天、昨天、最近一轮”时，先联网核实准确日期和正式赛果，再处理该范围。

## 来源优先级

按以下顺序采集并保留 URL：

1. FIFA 或赛事组织方官方比赛中心、官方技术报告。
2. 国家队、足协或球队官方阵容与比赛报告。
3. Opta、Stats Perform 等专业统计来源。
4. 可靠比赛统计平台。
5. 主流媒体比赛报告，仅用于补充事件、伤病、战术和采访。

同一关键事实发生冲突时，采用优先级更高的来源，并在 `notes` 中记录冲突。社媒不能作为比分、阵容或统计数据的唯一来源。

## 必须更新的数据

### 比赛基础数据

- 比赛编号、赛事、日期、阶段和场地
- 双方球队
- 实际比分
- 数据来源和可靠性

### 球队统计

- 射门、射正
- xG
- 控球率
- 角球
- 定位球进球、点球、乌龙
- 红牌
- 门将或后场重大失误
- 补时进球

来源没有提供某项时保存 `null`，不能将未知写成 `0`。

### 球员阵容身份

双方所有已实际出场球员都要保存：

- 球队、姓名、号码、位置和球员类型
- 首发、替补或未出场
- 是否队长
- 出场时间
- 替补登场和被换下时间

`full` 模式至少要求双方各11名实际出场球员。若可靠来源提供未出场替补，可一并保存。

### 球员进攻数据

- 进球、助攻
- 射门、射正
- xG、xA
- 关键传球、创造重大机会
- 对方禁区触球
- 盘带尝试和成功
- 越位

### 球员组织与防守数据

- 触球
- 传球尝试和成功
- 抢断、拦截、解围、封堵、球权恢复
- 地面对抗和高空对抗
- 犯规和被犯规

### 门将与纪律数据

- 扑救、失球、扑点
- 黄牌、红牌
- 乌龙
- 统计平台评分

### 比赛事件

保存可归因的关键事件：

- 进球和助攻
- 换人
- 黄牌和红牌
- 乌龙
- 点球扑救
- 门将或后场重大失误
- 事件分钟和补时分钟

每个事件使用稳定的 `event_ref`，重复更新同一比赛时执行覆盖更新，不制造重复事件。

## 自动更新步骤

1. 读取 `templates/post_match_player_data_template.json`。
2. 运行：

   ```bash
   python scripts/update_post_match_data.py --audit
   ```

3. 根据默认范围确定要处理的 `missing` 或 `partial` 比赛。
4. 联网核实正式赛果、完整阵容、球队统计、球员表现和关键事件。
5. 为每场比赛生成 `data/imports/<match_id>.json`；目录不存在时创建。
6. 使用模板中的全部字段。无数据字段填写 `null`，并保留来源。
7. 优先尝试 `data_completeness=full`。无法取得完整阵容或进球归因时改为 `partial`，不得伪装成完整数据。
8. 写入数据库：

   ```bash
   python scripts/update_post_match_data.py data/imports/<match_id>.json
   ```

9. 写入失败时根据错误修正 JSON 后重试；不得绕过校验直接操作数据库。
10. 按 `templates/post_match_review_template.md` 完成预测误差复盘，更新历史样本和标签。
11. 再次运行覆盖审计并检查 SQLite 完整性。
12. 向用户报告：
    - 成功更新的比赛
    - 每场球员记录数和事件数
    - `full`、`partial`、`missing` 状态
    - 缺失字段及原因
    - 采用的主要来源

## 完整度判定

### full

- 正式赛果已确认；
- 双方各至少11名实际出场球员；
- 出场时间和阵容身份齐全；
- 进球与乌龙归因合计和实际比分一致；
- 每名球员至少有来源；
- 数据库写入和审计通过。

部分高级统计缺失时可以保持字段为 `null`，但必须拥有完整出场名单、时间、进球和助攻归因。

### partial

- 赛果可靠；
- 只取得部分球员、部分出场时间或部分统计；
- 无法完成进球归因核对；
- 来源只支持部分数据。

`partial` 数据只能用于已有字段，不得推断缺失数据。

### missing

- 尚未导入球员逐场数据；
- 或现有数据无法通过基本校验。

## 更新原则

- 不要求用户重复提供公开可检索的数据。
- 不把未知值写成零。
- 不用新闻摘要替代完整技术统计。
- 不因单场表现覆盖球员长期能力，只新增逐场记录并在后续预测中做近期聚合。
- 重复执行必须幂等；更新同一比赛和球员时覆盖对应记录。
- 任一写入步骤失败时保持事务回滚。
